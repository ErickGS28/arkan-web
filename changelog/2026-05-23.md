## 1. Correcciones previas (blog y rutas)

### `/blog/[slug]` — error 404 en SSR
- Causa: `output: 'hybrid'` removido en Astro 5; se intentaba usar `@astrojs/node@10` incompatible.
- Fix: cambio a `output: 'server'` + `@astrojs/node@9`. Se eliminó `getStaticPaths`.

### Subida de imágenes en blog
- El endpoint `POST /blog/upload-image` tenía `@UseGuards(SessionGuard)` que bloqueaba requests cross-origin en dev.
- Fix: se removió el guard del upload; `sameSite` de cookie cambiado a `'lax'` en desarrollo.

### Cards del blog (index) sin estilos
- Causa: estilos Astro scoped no aplican a elementos creados vía `innerHTML` en JS.
- Fix: `<style>` → `<style is:global>` en `blog/index.astro` y `blog/[slug].astro`.

### Texto invisible en artículos de blog
- Causa: `body { color: #F0F0F0 }` del Layout oscuro heredado por sección con fondo blanco.
- Fix: `color: #111111` explícito en `.article`.

## 2. Módulo Encuestas

### Backend (`arkan-service`)

Nuevo módulo `SurveyModule` con 5 entidades y CRUD completo:

| Entidad | Tabla | Descripción |
|---|---|---|
| `Survey` | `surveys` | Encuesta con título, slug, estado (DRAFT/ACTIVE/CLOSED) |
| `Question` | `survey_questions` | Pregunta con tipo SINGLE/MULTIPLE/TEXT, orden, requerida |
| `QuestionOption` | `survey_question_options` | Opción de respuesta con orden |
| `SurveyResponse` | `survey_responses` | Respuesta con token UUID único |
| `ResponseAnswer` | `survey_response_answers` | Respuesta por pregunta (opción o texto libre) |

**API endpoints:**
- `GET /surveys` — listado admin (autenticado)
- `GET /surveys/public/:slug` — encuesta pública por slug
- `POST /surveys` — crear encuesta con preguntas y opciones
- `PATCH /surveys/:id` — actualizar (reemplaza preguntas completo)
- `DELETE /surveys/:id` — soft delete
- `POST /surveys/:slug/submit` — responder encuesta (público)
- `GET /surveys/:id/results` — resultados agregados por opción

**Deduplicación:** token UUID generado en cliente guardado en `localStorage` + restricción `UNIQUE` en DB. Previene doble envío.

**Fix FK crítico:** todas las columnas FK tienen `type: 'int', unsigned: true` para coincidir con los PKs unsigned de TypeORM.

## 3. Módulo Marcas — Categorías e Imágenes

### Backend (`arkan-service`)

Nuevo módulo `BrandModule` con 2 entidades:

| Entidad | Tabla | Descripción |
|---|---|---|
| `BrandCategory` | `brand_categories` | Categoría con enum de marca (ARUBA/BAKARI/BLACK_BASH), nombre, descripción, orden |
| `CategoryImage` | `category_images` | Imagen con URL de Cloudflare R2, alt, orden. FK con CASCADE. |

**API endpoints:**
- `GET /brands/categories?brand=ARUBA` — categorías con imágenes (público)
- `GET /brands/categories/:id` — una categoría con imágenes
- `POST /brands/categories` — crear categoría (admin)
- `PATCH /brands/categories/:id` — editar categoría (admin)
- `DELETE /brands/categories/:id` — eliminar categoría + borrar imágenes de R2 (admin)
- `POST /brands/categories/:id/images` — subir imagen a Cloudflare R2 (admin)
- `DELETE /brands/images/:id` — eliminar imagen de DB y R2 (admin)

Subida de imágenes usa `CloudflareService.upload(file, 'arkan/brands')` — mismo flujo que blog.

### Frontend — Admin

| Ruta | Función |
|---|---|
| `/admin/marcas/aruba` | Lista de categorías Aruba. CRUD con modales de crear/editar/eliminar. |
| `/admin/marcas/bakari` | Igual para BKR Bakari. |
| `/admin/marcas/black-bash` | Igual para Black Bash MX. |
| `/admin/marcas/categoria?id=X&brand=Y` | Grid de imágenes con upload + delete por hover. Barra de progreso. |

Sidebar actualizado: links de marcas apuntan a `/admin/marcas/{brand}`. Active state cubre sub-rutas.

**Tema visual:** fondo claro `#F6F6F6` (igual que blog/encuestas admin). Títulos `#0A0A0A`, tablas blancas, botones oscuros, modales con sombra.

### Frontend — Páginas públicas

`BrandCategories.astro` — slider horizontal:
- Muestra 3 imágenes visibles simultáneamente en desktop.
- JS mide `offsetWidth` del contenedor y asigna píxeles exactos a cada slide (evita problema de `%` en flex con overflow).
- `scroll-snap-type: x mandatory` — swipe nativo en móvil.
- Flechas prev/next aparecen cuando hay más de 3 imágenes.
- En tablet: ~1.4 slides visibles. En mobile: ~1.2 slides.

`aruba.astro`, `bakari.astro`, `black-bash.astro` — SSR fetch:
- En cada request SSR, consulta `/brands/categories?brand=X` con timeout de 3s.
- Si el API responde y tiene datos, los usa para renderizar el slider.
- Si el API falla o no hay datos, usa el contenido estático de `brands.ts` como fallback.
- En producción: agregar `API_URL=https://...` al `.env` del frontend.
